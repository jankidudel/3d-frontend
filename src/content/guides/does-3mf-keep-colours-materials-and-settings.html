A 3MF can store colours, materials and slicer settings, but whether they survive depends on the program that opens it. The shape and units usually carry over reliably. Colours and materials carry over only if the receiving program supports them, and slicer settings are often specific to one slicer. Keep the original project, and check each property you need in the program you will actually print from.

What carries over, and what to check

Information How 3MF stores it What InspectMesh checks What you check in the receiving program
Shape and units Standard meshes, sub-parts and a declared unit The shape, real size and unit Known dimensions and the imported shape
Parts and positions Stored objects and where each is placed Which parts are placed and their positions All expected parts, positions, and any re-centring
Display colours A basic colour per material, or colour and texture extensions Not checked: the preview shows shape only Colours on each face, textures and how they look
Real material and filament colour Material data plus how you map it to filaments Not checked Which filament or tool each part is assigned to
Slicer settings Program-specific settings, profiles, plates and supports Not checked Every setting you rely on, in the exact program and version

A colour shown on screen is not a promise of the printed colour or material. A file that opens correctly only tells you the shape loaded, not that every property survived.

Example: same shape, different saved setting

We made two PrusaSlicer 2.9.6 projects of the same box, "P-roof" and "P-open". They differ only in one per-object setting: the number of top layers. We reopened and sliced both with the same PrusaSlicer version from the command line. This tests one setting in one program, not the PrusaSlicer interface, colours or other slicers.

File Shape and setting Result
P-roof 30 x 30 x 10 mm box at X/Y 85 to 115; top layers 4 (global and per-object) Top surface printed at Z 10
P-open Same box and position; global 4, per-object 0 No top surface: the per-object setting wins
Exported STL in a fresh project Same triangles (moved by +85, +85, 0); fresh default of 4 top layers Top surface is back: the STL did not keep the per-object setting
InspectMesh Both projects: one part, 12 triangles, same size Shape fully read; one closed part, 9,000 mm³. InspectMesh does not apply slicer settings.

Details are in the project test record and the shape comparison record, which compares the actual triangles, not just sizes. The setting belongs to the ordinary object; there is no modifier mesh. Saving and reopening in the PrusaSlicer interface, textures, colours and other programs were not tested.

So an exported shape can be perfect while the print settings are lost. If the top layers change after import, check the saved settings; if a whole part is missing, see missing objects after import. Prusa's project documentation explains how PrusaSlicer saves projects; our test covers only the version and steps named here.

How to check a 3MF you are sending or receiving

Use the 3MF viewer for the shape and positions, then check colours and settings in the program that will print it.

  1. Keep the original project, and list the properties you need and the file version before exporting.
  2. Note both programs and their versions, and the exact steps. Reopen the export in the original program if your workflow needs it.
  3. Import it into the receiving program and compare dimensions, positions, colours and filament assignments.
  4. For each property, write down kept, changed, missing or not tested. Leave anything you did not check as not tested.
  5. Set any settings that did not carry over in the receiving slicer, then check the final layers for your printer and filament. Repeat the check after updating either program.

The receiving-file checklist has space for this. The 3MF Consortium's compatibility matrix shows which programs report support for which features; it does not test your file.

Keep the original when you send an STL

An STL can keep part positions in its coordinates, but it has no separate placements, part names, units, colours, materials or settings. The recipient can move or rescale it, so note any such step. InspectMesh's STL downloads are in millimetres; say so when you send them.

If only the shapes are needed, export combined or separate parts, and keep the original project for future changes. Converting an STL back to 3MF cannot recreate lost colours, materials, supports or profiles. For choosing between the formats, see 3MF vs STL.
