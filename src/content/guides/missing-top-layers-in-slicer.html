Use controlled slices to find the cause before changing the mesh. slug: missing-top-layers-in-slicer eyebrow: Slicer roof diagnosis heading: Why Are the Top Layers Missing in Your Slicer? ---

Start with the preview controls, then compare the source roof with the effective slicing settings. A closed mesh can be sliced without top skin, while an intentionally open vessel should remain open. Repairing the mesh is useful only when the source geometry is actually wrong.

This guide concerns absent software paths. If the full preview has a continuous roof but the produced surface has holes, investigate the actual print process separately; a mesh check cannot diagnose that physical result.

Restore preview visibility first

Restore the relevant full layer range, model-extrusion categories and any object isolation in your native slicer. If the roof appears in the same exact output, the display changed; reslicing or repairing the mesh is unnecessary. Record the output hash before comparing views. A native before/after visibility recording was not available for this experiment, so the figures below show parsed retained output rather than a claimed UI filter demonstration.

Same closed box, different top closure

R-box is the original closed 30 x 30 x 10 mm control: one shell, 12 triangles and 9,000 mm³ known material volume. All three runs use its identical bytes. PrusaSlicer 2.9.6 uses the full saved baseline: two perimeters, 15% rectilinear infill, four bottom layers, 0.20 mm layer/first-layer heights, 0.4 mm nozzle and explicit 0.45 mm widths. Adaptive layers and supports are disabled.

A designed opening is a different source

V2 has a 1.2 mm base and walls around an intentionally open cavity. Its ordinary output has a cavity floor at Z=1.2 and no roof at Z=30. Inspect source surfaces in the STL Viewer; visual clipping hides surfaces without generating a cap or extracting a solid section. Only an actually defective missing face belongs in the missing-surface repair workflow.

Check local settings and mode as well as the global profile

The controlled P-roof/P-open Prusa-format projects retain the same box geometry and global four-layer setting, but carry object-level top counts of four and zero. Actual CLI reopening produces roof/no-roof paths. The official exported STL has matching triangle geometry after the recorded placement translation; slicing it with the fresh ordinary baseline restores the roof. See the project-state comparison for construction, exact scope and resolver observations. This is a CLI project-reader comparison, not a claimed GUI save/reopen test.

A spiral-vase choice can intentionally remove top closure too. Prusa's layer/perimeter documentation describes its top-layer and minimum-shell controls. Check effective object overrides and the selected version before interpreting a global number.

Layer count and nominal depth are separate

Four nominal 0.20 mm layers represent 0.80 mm; four nominal 0.10 mm layers represent 0.40 mm. That is arithmetic, not a universal shell calculation. In R1, upper solid-infill categories occur at Z=9.2, 9.6 and 9.8, bridge infill at Z=9.4, and top-solid infill at Z=10. Read actual categories and heights; minimum thickness, variable schedules and other shell rules can change the generated result.

Finding Next action

Source lacks an intended face Correct that geometry, reopen the derivative, then reslice.
Top closure disabled Preserve source bytes, restore the required effective setting and verify top-solid paths.
Mode or local override changes the result Review saved project state and the mode owner before modifying the mesh.
