Before releasing a model collection, verify that every intended component is present, name the physical scale and keep a review record for the exact delivered versions. A geometry report documents completed checks; it cannot promise a successful print on every customer machine.

Start with the mixed example collection, then select your own files using the same settings. The closed 20 mm cube, open-face cube and malformed input demonstrate three independent outcomes. These are generated software fixtures, without physical print testing.

Worked release checklist: a three-file enclosure kit

Hypothetical delivery: base, lid and spacer, all intended in millimetres. Declare the expected overall bounds and the number of separate pieces before reviewing. A missing spacer is a delivery error even if the base has no topology findings.

Stage Record Release decision
Inventory base-r03.stl, lid-r03.stl, spacer-r02.stl; one each Compare actual package contents with this manifest
Scale Base 80 × 60 × 20 mm; lid 80 × 60 × 3 mm; spacer 10 × 10 × 5 mm Ask the author if the known dimension disagrees; do not guess from appearance
Mesh checks Completed edge/winding checks, intended shells, wall threshold, skipped fit Review each result independently; failed and skipped are not passes
Correction Retain base-r02.stl and separately export base-r03.stl Compare original and corrected surfaces plus affected holes and mating faces
Slicing Target profile, orientation and affected-layer observations Verify the receiving slicer; label any physical testing separately
Package Three named files, manifest, report, assembly note and applicable licence Reopen the delivered copies rather than only the working folder

Sample delivery manifest

Project: example-enclosure-kit
Release: 2026-10-07-r03
STL coordinate assumption: millimetres
Parts: base-r03.stl (1), lid-r03.stl (1), spacer-r02.stl (1)
Design references: base width 80 mm; lid width 80 mm
Review: collection-review-2 JSON + printable report
Change: base hole corrected; compare r02 against r03
Limitations: no physical print evidence; fit skipped without a profile
Recipient action: verify mating features and sliced layers

This manifest is a hypothetical template, not a measurement of a supplied kit. Use the actual filenames, measured bounds and quantities. Keep geometry files separate from the report history; browser-local reports can disappear when browser data is cleared. Export the report needed for your release record.

Compare repaired exports before publishing

Compare STL revisions in original coordinates first. Triangle counts can change with retriangulation while the surface remains the same; bounds can stay the same while a hole changes. Record both STL unit assumptions, any centre translation and review tolerance. Inspect functional details individually because surface sampling can miss them.

Do not treat an intentional separate shell as something to delete. If the intended cavity, joint or moving component is unclear, return to source CAD. Recheck the exported correction and the final delivery package after changes.

Write customer-facing limitations

Example note: “File findings were reviewed in millimetres using the attached settings. Printer fit was skipped. Self intersections, supports, material suitability and physical assembly are not certified by these checks. Confirm the intended dimensions and review your slicer layers before printing.” Replace this with what actually ran, including failures; rights to distribute are a separate requirement.

For customer-supplied work, use the intake decision workflow. To begin a release, run a local collection review, export its findings and keep version names consistent.

Prepare a local quote worksheet

After checking the intended files and scope, use the price calculator and printable quote worksheet to record quantity, currency, per-part work and once-per-order setup. Keep failure allowance separate from rates that already include it. The worksheet is an estimate, not an invoice or production acceptance; references stay local until deliberately exported.
