InspectMesh reports bounded geometry observations, not a print certification. Read the method, assumptions and unavailable checks alongside a finding. A closed-looking picture, zero edge findings or a completed operation each answers only part of the question.

Placed identity and export verification contract

The local viewer, converter, local preflight and collection path share a bounded core geometry resolver. It follows the package root model relationship, applies component then parent placement transforms and converts source units once to millimetres. Top-level build order supplies stable identities for repeated references. Unplaced resources contribute no build geometry. The server dimensions/quality methods remain separate methods with their own reports.

Status Meaning
Complete supported geometry Every placed item resolved within the implemented core mesh/component contract; project properties are outside the check
Unsupported required semantics Required namespace or cross-part geometry needs another application; no complete export offered
Invalid model data Malformed XML, invalid references, cyclic or nonfinite data; no omitted-item success
Processing limit reached Bounded file/expanded package, entry, component, geometry or precision budget

Limits are 25 MiB compressed, 20 MiB expanded, 1,024 entries, 500,000 triangles, 1,500,000 resolved vertices, 10,000 component visits and depth 64. Collection retains its stricter 5 MiB / 100,000-triangle budget. External relationships and uploaded links are never fetched. Recommended unsupported extensions conservatively stop for authoring-application review. Unknown optional properties alone do not block core geometry.

Exact serialized STL bytes reopen through the repository parser. Every oriented triangle is compared after Float32 rounding, allowing cyclic vertex order and preserving multiplicity. Count and bounds supplement this check. A half-ULP scale-based allowance with a 0.0000001 mm floor describes representation; exports exceeding a 0.01 mm allowance are rejected. Matching this geometry does not certify topology or physical printing.

Technical basis: 3MF Core specification 1.4.0, sections 3.3, 3.4 and 4.2; reviewed 11 October 2026. Examples are original mathematical controls, not physical print measurements or tests of every slicer.

Which actions process locally and which upload

The STL/3MF viewers open geometry locally. STL/3MF preflight, revision comparison, STL scale, STL reduction and the geometry converter also run locally. Loading an example fetches only a fixed public registry asset; it does not send your active model. Renderer code loads when the relevant tool needs it; this library uses lightweight static diagrams.

The viewer's optional issue-analysis action explicitly uploads the selected file to the quality-checker server workflow. Server quality checking and STL repair have their own processing disclosure. Do not interpret the local viewer's initial opening as server analysis, or assume the local methods are the same as every server checker. Review the privacy policy for policy and retention details before an upload.

Collection navigation can hold a selected File in this tab's memory for an explicit handoff. Reloading requires reselection. Optional collection history stores report data such as labels, settings, findings and bounded thumbnails in this browser, not original model bytes or full geometry arrays. Exported reports can contain private filenames and findings; choose where to share them yourself. Example URLs carry only a public allowlisted ID and canonicals point to the clean tool page.

Local 3MF triangle cleanup

3MF Repair accepts supported mesh packages up to the current 25 MiB file limit and processes them in this browser. A package must resolve before a removal plan is available; invalid indexes that stop resolution need a fresh source export. Selected operations remove duplicate vertex-index triples (ignoring order), relative-tolerance degenerate faces or supported invalid-index triangle elements. It does not fill holes, weld vertices or correct winding.

Coordinates and surrounding model XML text remain while selected triangle elements are removed. Decompressed payloads of other ZIP parts are retained; the compressed archive is regenerated. Reopening through the local parser checks supported resolution, not every extension or receiving-application assignment. A shared resource edit can affect several placements. Review the repair workflow and reopen the exact saved bytes in the target application.

The removal-plan screen skips duplicate, degenerate and invalid-index faces for its source-index edge counts; edge keys span the selected model part and are not isolated per resource. Treat these as plan diagnostics, not a complete topology report. Server quality checks instead use exact-coordinate incidence per placed build item, retaining duplicate-face incidence and summing counts. Server and local 3MF preflight do not run a spatial intersection check; STL local preflight has its separate bounded BVH screen. No method here certifies full package or extension validity.

Read result states literally

  • Completed: the supported operation returned a result; inspect warnings and scope.
  • Warning / needs attention: review a finding against units, design intent and the intended process.
  • Skipped / unsupported: the method did not run or cannot answer this question. It is not a passing result.
  • Sampled: a bounded set of observations, not exhaustive coverage.
  • Failed: no usable result from that operation. Do not read an empty report as zero defects.
  • Unavailable volume: no supported solid-volume interpretation, not zero material.

How the examples were produced and verified

The example library contains eight teaching scenarios with stable IDs, original generated geometry, known dimensions, downloadable bytes and original explanatory diagrams. Regression checks read those distributed files, run the actual local implementations and reopen generated STL output. They distinguish duplicate facets, reversed winding and stored normal vectors, resolve 3MF instances/units/transforms and check nominal fit arithmetic independently. These are software controls, not customer models or physical prints.

The coupon derivatives use meshoptimizer 1.2.0, relative error 0.01 and LockBorder. Actual retained PrusaSlicer 2.9.6 Classic/Arachne exports use a 0.4 mm nozzle, 0.2 mm layers, 0.45 mm extrusion width, two perimeters, zero infill and thin-wall option off. Their configuration footers remain available in preview-only G-code. No printer was controlled; a slicer estimate is not measured print time. The guide explains the recorded experiment and its limitations.

Technical basis and review boundary

The 3MF Core Specification defines units, resources, build items and transforms. meshoptimizer documents simplification constraints; Prusa's Arachne documentation explains variable-width perimeters. Reviewed 10 October 2026 alongside the application code. These references support specific method claims; no standard certifies the whole application and no expert reviewer credentials are claimed.

G-code evidence and per-metric coverage

The browser worker reviews a conservative linear model: G0/G1, G20/G21, G90/G91, G92, M82/M83 and temperature targets M104/M109/M140/M190. It starts logical XYZ/E at zero with millimetres and absolute modes until declared otherwise. These are disclosed model assumptions, not measured machine state. G92 E resets logical extrusion; G92 XYZ makes machine-frame extents incomplete. G90/G91 after explicit E modes, and M82 under relative XYZ, are marked firmware-dependent, as Marlin M82 and Klipper commands describe different interactions.

Recognised auxiliary fan/display/query/wait actions are outside geometry rather than automatically classified as bad paths. Unknown commands, arcs, macros and tool behaviours are not executed; unsupported state effects make subsequent linear/extrusion extents incomplete. The original line, escaped text excerpt, interpretation and next action remain inspectable. Evidence retains at most 100 groups with up to three 240-character samples each; temperature targets retain a bounded sample. Counts and first/last lines distinguish repeated findings from one event.

At most 200,000 source lines are reviewed; a source line over 4,096 characters produces an explicit unavailable import to bound parameter processing. The preview retains the first 50,000 moves; extents use all reviewed linear moves and disclose source truncation separately. New file loads terminate previous workers and invalidate stale findings/offers through request identity. No raw file is saved automatically. Report version 2 records metadata declarations, byte size/hash when available, coordinate assumptions, manual inputs and limitations; JSON/copy/print/PDF share one record without full source or path arrays.

PrusaSlicer 2.9.6 normal-mode elapsed duration and unambiguous single-filament grams declarations use the official processor time-comment implementation and per-filament statistics implementation, reviewed 10 October 2026. Comma-separated tool consumption is not collapsed. Length-only declarations are not automatically converted without verified diameter/density and scope. A slicer label is an unverified file declaration; a supported value is neither physical measurement nor authenticated provenance. Path uncertainty and declaration availability are separate metrics.

Operation-specific reducer verification

Reducer candidates start independently from the retained original. Each is serialized once, then those exact bytes reopen through the STL parser; the download reuses that blob. The verifier compares every intended output triangle under Float32 storage, retaining winding and multiplicity. For encoding, intended output is the source triangle geometry. For simplification, intended output is the algorithm's derivative: it is not expected to equal the original.

Count and 84 + 50N binary byte arithmetic supplement the triangle check. Original and candidate use the shared exact-coordinate topology screening up to 100,000 triangles. Boundary, over-shared, duplicate, degenerate and winding-conflict counts are compared; unavailable screening is labelled. Self intersections and defect locations are not checked. Increased finding counts require diagnostic-download acknowledgement, not a repaired or safe badge.

Comparison is explicit, uses the existing bounded worker and retains candidate identity and unit/tolerance basis. Candidate replacement or removal clears associated results; source replacement cancels work and suppresses late responses. Up to three derivative blobs remain in tab memory without automatic raw-file persistence.

Human dimensions and offsets show up to three decimals; small nonzero values and diagnostic errors use significant digits or scientific notation. Unavailable is distinct from zero. Geometry serialization, JSON numbers, tolerance tests and boundary decisions retain stored precision. Display resolution does not establish physical accuracy.
