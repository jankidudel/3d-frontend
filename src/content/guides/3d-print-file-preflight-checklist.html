Use this checklist as the last file-level sweep before slicing an STL or 3MF. It produces three outcomes: pass when the property is understood, warn when it needs slicer or design review, and fail when scale, geometry or intended content is unknown. For explanations and repair routes, use the complete print-readiness guide.

1. File and visual sanity

  • Pass: the expected objects open and their visible shape is plausible.
  • Warn: placement or orientation looks unusual but can be checked in the slicer.
  • Fail: objects are missing, empty, badly corrupted or unexplained.

Open the copy you will actually slice. Use the STL Viewer or 3MF Viewer, but remember that a normal-looking surface can still contain topology faults.

2. Dimensions, units and printer fit

  • Pass: X, Y and Z match a known reference and fit the usable build space.
  • Warn: a tested rotation is needed or space for a brim, supports or exclusion area is tight.
  • Fail: the unit assumption is unknown or a required axis exceeds the usable limit.

Check the bounding box with the STL Dimensions Checker or 3MF Dimensions Checker. STL does not declare a physical unit, so a 25.4-times error often indicates an inch/millimeter mismatch. The printer-fit guide covers rotations and usable-volume caveats.

3. Mesh integrity

  • Pass: findings are understood and consistent with the intended model.
  • Warn: the slicer must be checked for a localized or intentional condition.
  • Fail: open, non-manifold, inverted or intersecting geometry makes the intended solid ambiguous.

Run the STL Quality Checker or 3MF Quality Checker. Watertightness, manifold topology and face orientation answer different questions. Do not repair every warning automatically: locate it, compare it with the source, and decide whether it changes slicing or function.

4. Thickness and complexity

  • Pass: critical walls have been reviewed for the intended process and detail level is useful.
  • Warn: sampled thin regions or a high triangle count need closer inspection.
  • Fail: required walls disappear in preview or the file cannot be handled reliably.

Use the relevant STL wall-thickness or 3MF wall-thickness check as a screen, then verify perimeters and layers in the slicer. Triangle count is not a quality score; reduce geometry only for a demonstrated workflow problem and check for lost curvature or features afterward.

5. Verify every changed copy

Preserve the original. After repair, scaling, conversion or reduction, reopen the saved result and repeat only the affected checks plus a visual comparison. Confirm dimensions, object count, topology and triangle count where relevant. A successful save message does not establish that design intent survived.

Stop conditions

Do not move to slicing when the intended unit is unknown, a required object is missing, the model exceeds the usable build space, or a repair changed a functional surface without a reliable reference. Return to the author or source CAD when design intent cannot be recovered from the mesh. If the file passes geometry checks but the slicer drops regions or produces unexplained toolpaths, preserve the file and investigate the slicer-specific result rather than repeatedly applying mesh repairs.

A warning can proceed only when its consequence is understood and the next validation step is named. “The slicer accepts it” is insufficient when a required feature, dimension or material region may have been discarded.

Before you slice

  • The file contains the expected geometry.
  • Dimensions and unit assumptions are confirmed.
  • The model fits the usable printer volume with required allowances.
  • Mesh findings are understood rather than merely hidden.
  • Critical thickness and complexity concerns were reviewed.
  • Any modified copy was inspected again.

Keep a small record beside important jobs: source filename and revision, expected overall dimension, printer/profile, checks that produced warnings and any transformation applied. This turns the checklist into a repeatable handoff rather than a memory test. When another person reviews the job, they can see which assumptions were verified and which remain for the slicer or printer.

Re-run preflight when the source file changes, even if the filename does not. A revised mesh can restore an old scale, remove a component or change topology. Do not carry a prior pass forward based only on visual similarity.

File preflight cannot guarantee a successful print. Orientation, supports, adhesion, process settings, material behaviour, calibration and structural use still belong in slicer and engineering review.

Turn a collection into a reproducible handoff

A useful handoff records what was checked, what was assumed and what was left unresolved. The built-in mixed collection demonstrates three outcomes: a closed 20 mm cube with screened volume of 8,000 mm³; an open cube with four boundary edges and unavailable volume; and malformed input that fails independently. A single bad file does not erase the successful results.

Export settings with findings: check schema/version, STL unit assumption or 3MF declared unit, selected nominal printer, wall-review threshold, sampling method and unsupported checks. Explain that sample count describes coverage, not accuracy. File names and customer notes belong in your own local report, not analytics events.

Sort actionable findings first and name the next action: inspect size, correct an export, review a thin region, or request clarification. A local saved report is browser history rather than a cloud project. Keep original files unchanged; repairs should generate a separate copy and receive their own verification.
