Sequential printing needs clearance around the print head and gantry, not just bed space for each footprint. While the next object is being built, an already completed object can occupy space needed by the moving head, gantry, rods or cables. Review the exact native slicer/profile, object heights and print order.

Plan and side views answer different questions

The bed planner screens rectangular XY envelopes on rectangular or circular usable regions. It does not have a verified machine head shape, gantry height, cable motion or firmware routine. Its confirmed count can help cost a planned plate, but that count does not approve a sequential machine job.

The planner now screens rectangular envelopes on declared rectangular or circular regions and checks accepted reserved rectangles for nonoverlap and selected spacing. Neither circle containment nor that gap supplies head shape, gantry height or collision order. Use process-space budgeting for envelope reservations, then retain native sequential checks as a separate stage.

A hypothetical order review

Two objects have separated 30 × 30 mm footprints. One is 20 mm tall and the other 90 mm tall. Both footprints fit the entered bed. If the tall object finishes first, the later head/gantry route may pass beside or above it. Reversing order changes which completed object is present, but does not by itself prove clearance. The exact machine geometry and native profile checks are needed for either order. These example heights are not recommended clearance limits.

A speed value or a longer estimated duration cannot establish head/gantry clearance or correct object order. Those depend on geometry, the exact profile and the reviewed sequence, even when every requested rate is understood.

Where native checks belong

Prusa's sequential-printing documentation describes Complete individual objects and order review. It distinguishes advanced collision handling for supported Prusa profiles from generic clearance settings for other printers. Generic radius/height settings represent a simplified shape, not universal hardware dimensions. Use the current exact profile and printer instructions; the documentation also states that an identified collision error need not block G-code export. A downloadable file is not evidence that the warning was resolved.

Make the review reproducible

  1. Keep the original project and record application/version, machine/profile and object revisions.
  2. Check XY placement and allowances in the native slicer.
  3. Enable the intended sequential mode deliberately; inspect order, heights and native clearance findings.
  4. Recheck after changing order or placement. Retain unresolved warnings and obtain printer-specific guidance rather than entering guessed radii.
  5. Use G-code evidence only for the supported paths and declarations it actually recognises.

Use the layout workflow for placement, then keep native sequential collision checks separate. The read-only G-code viewer retains supported path evidence; it cannot approve head clearance.
