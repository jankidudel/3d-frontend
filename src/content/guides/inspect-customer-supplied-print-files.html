For a customer-supplied file, resolve size and design intent before quoting a print. Report observable findings in plain language, ask for the missing reference dimension when needed, and avoid treating automatic cleanup as permission to change the part.

First clarify units and expected size

Illustrative request: a bracket is intended to be 50.8 mm wide, but an STL arrives with width 2 coordinate units. A millimetre assumption gives 2 mm; an inch assumption gives 50.8 mm. Ask which dimension is authoritative before producing a quote. STL does not carry the answer.

A supported 3MF can declare units and build transforms. A readable package still does not prove that embedded printer settings are appropriate for your own machine. Use 3MF preflight for the resolved build, and explain any unsupported package features separately.

Example finding written for a customer

“The reviewed copy has four boundary edges around a missing face. Closed-model volume is unavailable. Size was interpreted as millimetres; nominal printer fit was skipped pending a confirmed printer. Please provide a replacement solid export or confirm the intended open surface.” That statement describes evidence and a next action without claiming the model cannot ever be sliced.

The example collection reproduces that open-face finding. It also demonstrates a malformed file failing independently. Export the report with settings, sampled-check status and source filename; do not send private customer text or file metadata to analytics.

Quote only the confirmed process

  1. Confirm expected dimensions and permitted modifications.
  2. Review geometry and nominal printer fit.
  3. Choose the actual profile and inspect the sliced layers.
  4. Read complete filament and duration estimates including supports and purge.
  5. Use the price calculator with explicit per-item and per-order costs.

One setup charge spread across five copies is different from five separate setups. A fit result based on nominal volume does not include brims, clips or excluded regions. If the part is too large, discuss splitting or scale changes before assuming either is acceptable.

Retain the evidence locally

Keep original and revised files separately. Use revision inspection to review an agreed replacement export. Browser-local history is not a cloud customer-management system; exported reports remain your responsibility to store appropriately. This is a practical file-review workflow, not legal or contractual advice.
