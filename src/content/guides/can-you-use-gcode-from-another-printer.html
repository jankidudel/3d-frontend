Usually not safely. G-code is a list of machine instructions made for one printer, firmware, nozzle and filament setup. A matching bed size or a comment naming a printer does not make it compatible with yours. Ask for the original model (STL or 3MF) or slicer project instead, and slice it yourself with your own printer profile.

What each kind of file gives you

What you received What it tells you What is missing
STL or 3MF model The shape, size and (in 3MF) placement Printer profile, filament and start/end code
Slicer project The settings and placement, if that slicer saves them Whether those settings suit your hardware and firmware
Only G-code Its comments, moves and commands An editable model, the full profile used and the printer it was made for

What to ask the sender

Note which version you received before reviewing it. A filename alone is not enough. A SHA-256 hash proves a file is identical byte for byte, but not who made it. Keep private filenames and notes in your own records, not in public links.

Record Ask for
Version and purpose Their version, the date received, the file hash, the number of parts and which run it is
Source files The model, the original project, and the slicer name and version used
Printer and firmware Exact model and revision, any modifications, firmware version
Profile and filament Nozzle, filament and tool assignments, usable bed area and origin, and units and extrusion mode
Speeds and overrides Feed rate units, speed and flow percentages, and which firmware and profile they assume
Machine routines Homing, offsets, macros, start and end code, tool changes
Only G-code received? Yes or no, plus your request for the model or project

Example: same bed size, different printer

Printers A and B both have 220 x 220 mm beds. A's G-code assumes the bed starts at X/Y zero, one tool and a particular homing macro. B's bed origin, tool offsets or macros differ. The equal bed size does not cover any of these differences, and a comment naming printer A is just a label. Ask for the project, check you have the right version, and slice it with B's own profile in the slicer. Don't try to edit individual commands by guesswork.

There is no universal way to "translate" G-code between printers. A browser preview shows the moves but does not run macros, identify the profile or approve temperatures. Klipper and Marlin each document their own macros and extrusion behaviour, and one does not tell you how the other behaves.

What to do

  1. List the files you received and the printer they are for.
  2. Look through the file for commands your printer may not support, without running it.
  3. Ask for any missing project or profile details. If in doubt, re-slice the model yourself.
  4. Only rely on the file's time or filament estimates once you know which units and settings they assume.
