Objects usually "go missing" after a 3MF import for one of four reasons: the object was stored in the file but never placed on the build plate, it is placed off-screen or below the bed, it is hidden or disabled in the program you opened it in, or the file uses a feature that program cannot read. Check which parts the file actually places before trying any mesh repair.

Step 1: know what should be there

Keep the original file and ask which parts the recipient expects. A part name, a stored shape, a placed part and a connected piece of surface are four different things. One placed part can contain nested sub-parts, and splitting a model into pieces will not tell you which part each piece belonged to.

Example file Stored shapes / placed parts What you see
One placed cube 1 / 1 12 triangles; 20 mm cube
Two placed cubes 1 / 2 24 triangles; X 0 to 60 mm; second cube at X 40 to 60 mm
Extra unplaced shape 2 / 2 One more stored shape, but the build is still 24 triangles at X 0 to 60 mm
Inch file, moved 1 / 1 12 triangles; 25.4 mm cube at X 50.8 to 76.2 mm

Step 2: find the part you expect

  1. Open the two-cube example in the 3MF viewer. Both build-1 and build-2 use the same stored cube.
  2. Select build-2, then Isolate selected and Frame selected. Its position (X 40 to 60 mm) appears next to the whole build's size.
  3. Choose Show all, then compare with the object list in your slicer: is the part there but hidden, disabled or off-screen?
  4. Note if your slicer moved, scaled or re-centred anything, or pushed a part below the bed. A part can exist without being in view.

We reran this check on 27 October 2026; see the filled-in check record. We have not tested other slicers, so note your slicer's name and version with what you see. Isolating a part only changes the view; choosing what to export happens separately in the converter.

Never placed is different from unreadable

Compare the one-cube file with the file with an extra unplaced shape. A shape that is stored but not placed adds nothing to the build. Don't place every stored shape automatically, and don't delete repeated placements as if they were duplicate meshes.

If a placed part points to a shape that does not exist, InspectMesh stops with a specific error instead of quietly dropping that part. Files that rely on features InspectMesh does not read, or that reference parts in a loop, need the original program. A file failing to open does not by itself tell you why.

The part is there, but a setting changed

Sometimes nothing is missing: a part's settings changed instead. Our "P" example pair both open as one part with 12 triangles at the same position (X/Y 85 to 115 mm, Z 0 to 10 mm). The only difference is a per-object setting for top layers (4 versus 0), which changes whether a top surface is printed. There is no separate modifier or missing part.

Exporting to STL cannot bring back project settings.

What you see, and what to do

What you see Likely cause What to do
The part is out of view Its position, scale, the camera, or the slicer moved it Check its position and zoom out to the whole scene
A shape is stored but not placed It was not meant to be in this build Ask the designer whether it should be placed
The file uses unsupported features The program cannot read the whole design Use the original program and keep the original file
The part is there, but the project differs A setting or property was not kept Check what 3MF keeps

Once everything is accounted for, choose another 3MF check. To open a 3MF for the first time, see how to open a 3MF file; if it then fails to slice, see why won't my 3MF slice. Note that a correct part count does not guarantee a volume: our two separate cubes still give no volume, because InspectMesh only measures a single connected part.

Decide whether to export combined or separate STLs only once you know what the file contains. An exported STL can keep the positions, but loses which stored shape each part came from.
