Convert STL to a basic 3MF when you want to package an existing mesh with a known coordinate unit. The conversion does not recover CAD features, repair the mesh or create slicer settings that were absent from the STL. Keep the source and verify the saved package.

Why choose this output?

A compatible receiver can read an explicit coordinate unit from a basic 3MF. That is useful when you already know what the STL coordinates mean; it does not discover their intended physical size. Establish the unit interpretation with a known dimension first.

Convert once, keeping the original

  1. Preserve the STL and establish its intended physical unit.
  2. Check that the mesh represents the intended object. Conversion will carry its existing surface problems into another container.
  3. Choose the STL in the local converter. ASCII and binary inputs up to 25 MiB are processed in the browser without upload.
  4. Select what the existing coordinates mean. Do not use unit selection as an unverified resize operation.
  5. Convert and download a separately named 3MF.
  6. Reopen it in 3MF Viewer or local preflight. Compare physical dimensions, intended geometry and the basic build structure.
  7. Check the receiving slicer before replacing a workflow input.

Selecting inches is correct only when those coordinates were intended as inches. The converter cannot discover that intent. If the required edge is 20 mm, declaring the same 20 coordinates as inches creates the wrong physical size rather than fixing one.

When to stop

If the unit cannot be established, the expected object is missing or the reopened size disagrees, keep the source and resolve the cause. Do not repeatedly relabel or scale a file until it looks plausible. Use the scaling workflow only when an actual coordinate change is justified. A basic build cannot recreate absent colours, material assignments, native CAD history or application-specific print settings.
