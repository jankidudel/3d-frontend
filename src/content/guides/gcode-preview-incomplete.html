An incomplete preview can come from unsupported motion or state changes, a bounded renderer, unreadable input or malformed text. Those cases need different next actions. Read each metric's coverage instead of treating the picture or number of recognised lines as a machine compatibility score.

Text recognition is not extension recognition

Renaming a binary container to .gcode does not make it plain text. Prusa documents a binary G-code format and native conversion/viewing support; InspectMesh does not decode that format or vendor containers. Import rejects undecodable bytes and control characters. A readable extension still needs successfully parsed instructions. Files are limited to 25 MiB; source lines over 4,096 characters are unavailable to keep parameter processing bounded.

Which metrics can remain useful?

A supported PrusaSlicer 2.9.6 normal-mode duration comment can remain a recognised declaration when an arc makes extents incomplete. It is neither measured elapsed time nor proof that every path was inspected. A missing or ambiguous consumption field remains unavailable, never zero. Multiple tools cannot be silently collapsed into a single spool; unsupported length metadata needs manual interpretation and confirmed diameter/density before mass conversion.

Mode assumptions also matter. G90/G91 after M82/M83 is disclosed as firmware-dependent extrusion classification in the conservative model. G92 E resets logical extrusion without ordinary XYZ movement; G92 XYZ changes the frame and does not prove machine-space bounds.
