Understand the count you received

In the owned example, one mesh resource contains 12 triangles. Placing that resource twice produces an expected resolved total of 24 triangles. This is a count of placed geometry, not a second stored mesh resource, a print-quality grade or an estimate of toolpath time.

Compare one placed cube with two placed cubes. These owned packages demonstrate instancing. The guide retains a separately labelled local processor observation; it does not establish the deployed endpoint revision.

Triangle count alone does not establish toolpath time or physical print quality. Compare critical surfaces at the intended size and use the actual slicer outcome before claiming a performance improvement.

Investigate stored resources and placed counts.

What happens to the count when you export STL

STL has no instancing, so every placed copy is written out in full. Use the placed count, not the stored count, to predict an exported STL.

3MF situation Triangles in the exported STL
One 12-triangle cube placed twice, entire build exported 24, about 1.3 KB as binary STL (84 + 50 x 24 bytes)
The same build, one placed item exported 12, that item's placement only
A stored object that no build item references Not counted and not exported

The 3MF to STL converter offers both the entire-build and single-item exports.
