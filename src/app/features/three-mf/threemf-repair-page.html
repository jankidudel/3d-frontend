What changes inside the package

This browser tool removes selected duplicate, degenerate or invalid-index triangle elements from the relationship-selected model XML. It keeps vertex coordinates, other XML elements and the decompressed payloads of other ZIP parts. It creates a new compressed package; the ZIP bytes and compression layout are not identical to the original. Retaining a vendor setting as a payload does not prove a receiving slicer will use it correctly.

A duplicate-face example

Download the duplicate-face cube package. It declares millimetres, one mesh and one build item. Expect 13 source triangles and one duplicate. Leave only duplicate removal selected, run the local repair and compare the before/after counts: 13 to 12 triangles, with no intended dimension change. Save the repaired package and open it again in 3MF Preflight and your receiving slicer. This is generated mathematical geometry, not a physical print test.

Source mesh counts and placed geometry answer different questions

The removable-triangle plan examines mesh definitions in the model XML; the preview resolves supported build items, component references and transforms. A shared resource can have several placements without several independent repair operations. Compare the declared unit, resolved build count and dimensions before trusting the saved copy.

Unsupported or unresolved packages produce an error rather than a flattened replacement. Open edges, non-manifold connectivity, self-intersections and missing surfaces are not reconstructed. This local plan does not correct winding. An empty plan means no supported removal is selected, not that every possible issue has been checked.

Preserve the original project, especially where colours, textures or printer profiles matter. If the receiving slicer loses an assignment, stop and review the original package there; check core geometry and slicer-project information separately.
