What a saved copy does and does not preserve

This browser tool removes selected duplicate, degenerate or invalid-index triangle elements from the relationship-selected model XML. It keeps vertex coordinates, other XML elements and the decompressed payloads of other ZIP parts. It creates a new compressed package; the ZIP bytes and compression layout are not identical to the original. Retaining a vendor setting as a payload does not prove a receiving slicer will use it correctly.

Stored shapes vs placed objects

The removal plan looks at each stored shape in the file, while the preview shows the objects as placed. One stored shape can be placed several times, so fixing it once fixes every copy. Compare the unit, the number of objects and the size before trusting the saved copy.

It finds triangles that use the same three corners as another triangle in the same shape, in any order, and leaves out duplicate, zero-area and broken triangles when counting edges. These counts are a rough guide for the plan, not a full check of each object. A file too broken to open never reaches the plan. Check the saved file again with another tool.

Files it cannot read give an error instead of a half-converted result. It does not rebuild holes, non-manifold joins, overlaps or missing surfaces, and it does not flip faces. An empty plan means there is nothing it can remove, not that the file has no other problems.

How to repair a 3MF and check the saved file. Several placed objects can share the shape you edited, so check the number of objects, their positions and the size after saving. These links do not send your file anywhere.

Keep the original project, especially if colours, textures or printer profiles matter. If your slicer loses a colour or material, stop and check the original file there; shapes and slicer settings are checked separately.
