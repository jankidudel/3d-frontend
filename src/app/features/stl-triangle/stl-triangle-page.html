What the count means

The server reports the triangle records parsed into this mesh, including duplicate or degenerate records that later validation can flag. It does not deduplicate them into unique faces or identify named CAD objects. A count does not prove valid topology or preserved detail. Malformed input and processing failures are not zero-triangle results.

Triangle count and binary STL file size

A binary STL stores an 80-byte header, a 4-byte triangle count and exactly 50 bytes per triangle, so its size follows directly from the count: bytes = 84 + 50 x triangles. ASCII STL writes each triangle as text and is typically several times larger for the same mesh.

Binary STL size calculated from triangle count
Triangles Binary STL size Example
12 684 bytes The closed 20 mm cube control
100,000 about 4.8 MiB A moderately detailed functional part
524,286 just under 25 MiB The largest binary STL this counter accepts
1,000,000 about 47.7 MiB Too large here; consider reducing it first

If a binary file's size does not match this formula, the file may be truncated or padded, which is worth checking before you trust any count.
