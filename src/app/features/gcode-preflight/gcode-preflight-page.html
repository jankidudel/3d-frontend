G-code preflight FAQ

Can this prove a file is safe to print?

No. Firmware, machine configuration, material, calibration, start G-code and slicer profile affect the print.

Why can the parsed preview be incomplete?

Arcs, macros, conditional logic, multiple tools and vendor-specific commands can limit a browser parser.

Parsed paths are only part of the machine instructions

This browser-local review supports common linear moves and coordinate/extrusion mode changes. G2/G3 arcs are not included in preview extents. Unsupported or malformed commands are disclosed; macros, tool changes and firmware dialect behaviour need the exact machine documentation.

With absolute millimetre coordinates and absolute extrusion, G1 X20 E1 followed by G1 X40 E1 has a move with extrusion, then a move without additional extrusion. Under relative extrusion the same E1 fields mean something different. Confirm mode commands before interpreting paths using the worked extrusion-state tables. For a surprising F value, use mm/min versus mm/s. The existing example selector above includes both analytical extrusion-mode controls; loading one deliberately replaces the current result. These snippets are not printable jobs.

The retained Classic example export was generated with PrusaSlicer 2.9.6 for software inspection. It is not a qualified machine profile and should not be executed on a printer. Preview does not certify temperatures, start/end routines, homing, usable motion limits or machine safety.

Use the G-code review procedure, the original slicer and your exact printer profile for the final decision. Parsed layer counts and duration comments are observations, not measured print time.
